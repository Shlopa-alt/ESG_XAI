# Студия анализа

Сценарии обработки и анализа данных из узлов — перенос функционала Loginom (бывш. Deductor) на
платформу. Сайт: «Инструменты» → «Студия анализа».

## Как устроено

| Часть | Где | Что делает |
|---|---|---|
| Редактор | `frontend/src/pages/StudioEditor.tsx` (React Flow) | холст узлов, палитра, настройки узла, «Таблица» и «Статистика» результата |
| Сценарии | `backend/app/api/studio.py`, таблицы `scenarios`, `scenario_versions`, `studio_runs` (миграция 0026) | SC-NN, версии, права, постановка расчёта, приём итога |
| Движок | `runner/studio/` (`engine.py`, `components.py`, `expr.py`, `stats.py`) | проверка сценария, счёт узлов по связям, компоненты, выражения |
| Исполнитель | `runner/worker/tasks.py`: задача `runner.studio`, очередь `studio` | сверка sha256 входных файлов, расчёт, итог платформе |

Сценарий — JSON (`format: 1`): узлы (`id`, `type`, `params`, координаты) и связи
(`from` → `to`, вход `port`). Каждое сохранение — новая версия; расчёт записывает версию сценария,
sha256 каждого входного файла, коммит runner и хеш окружения (правило 3).

**Предпросмотр узла** («Посчитать узел») считает только узел и то, от чего он зависит; первые
100 строк результата и статистика по столбцам приходят на сайт, файлы не сохраняются.
**Расчёт сценария** считает всё; узлы «Экспорт: Файл» сохраняют CSV/Excel в папку данных
(`studio/SC-NN/run-NNNNN/files/`), их можно скачать со страницы сценария. Ошибка узла не
останавливает остальные: не считаются только узлы после него.

Права: смотреть — все вошедшие; создавать, менять, считать — researcher+; менять — автор или
владелец платформы (остальные — «Сделать копию»). Результаты по набору под NDA видны только тем,
кому видны его файлы (правило 6).

## Компоненты (этап 1)

Импорт: **Набор данных** (версия набора платформы — CSV или лист Excel).
Экспорт: **Файл** (CSV или Excel).
Трансформация (как в Loginom): Группировка, Разгруппировка, Дата и время, Дополнение данных,
Замена (точно / регулярным выражением), Калькулятор, Кросс-таблица, Объединение, Параметры полей,
Свёртка столбцов, Скользящее окно (лаги и прогнозный горизонт, в т.ч. внутри групп — панели),
Слияние (внутреннее, левое, правое, полное, разность), Соединение, Сортировка, Фильтр строк.
Визуализаторы: Таблица, Статистика.

**Выражения** (Калькулятор, Фильтр строк) — как в Excel: `выручка / сотрудники`,
`ЕСЛИ(roe > 0.1; "высокая"; "низкая")`, `ГОД(дата) >= 2020 И НЕ ПУСТО(отрасль)`; столбец с пробелами —
в обратных кавычках: `` `доля, %` ``. Функции: ЕСЛИ, ABS, КОРЕНЬ, LN, EXP, ОКРУГЛ, МАКС, МИН, ПУСТО,
ПЕРВОЕНЕПУСТОЕ, ГОД, КВАРТАЛ, МЕСЯЦ, ДЕНЬ, ТЕКСТ, ЧИСЛО, ДЛСТР, ПРОПИСН, СТРОЧН, СЖПРОБЕЛЫ, СЦЕП
(и английские имена). Разбирает свой разборщик с белым списком — произвольный Python не выполняется.

## Компоненты (этап 2)

Предобработка (`runner/studio/preprocess.py`): **Заполнение пропусков** (среднее, медиана, частое,
значение, предыдущее/следующее, интерполяция, удалить строку — в т.ч. внутри групп), **Квантование**
(равной наполненности, ширины, свои границы), **Конечные классы** (классы по связи с бинарным
целевым, WoE), **Разбиение на множества** (обучающее/тестовое/валидационное, группа целиком в одно
множество, стратификация, seed), **Редактирование выбросов** (IQR, z, квантили: обрезать, пусто,
удалить, отметить), **Сглаживание** (скользящее среднее/медиана, экспоненциальное, внутри групп),
**Сэмплинг** (долей, числом, по слоям, бутстреп, seed), **Нормализация** (z, 0…1, медиана/IQR,
логарифм; дискретные — столбцы 0/1, номер, частота).

Исследование (`runner/studio/research.py`): **Корреляционный анализ** (Пирсон, Спирмен, Кендалл —
парами с p-значением и силой, с целевым или матрицей), **Факторный анализ** (главные компоненты,
число факторов по Кайзеру, варимакс; нагрузки и доля дисперсии или факторы в строки),
**Автокорреляция** (ACF, частная PACF, граница значимости), **Дубликаты и противоречия**.

Визуализаторы: **Качество данных** (пропуски, выбросы, нули, числа текстом, постоянные столбцы,
повторы строк) и **Диаграмма** (гистограмма по всем строкам; столбцы, точки, линия — по случайной
выборке до 500 строк у узла, посчитанного «Посчитать узел»).

Дальше (этапы 3–5): Data Mining (регрессии, нейросети, кластеризация, ARIMAX, ассоциативные
правила…), управление (подмодели, условия, циклы, переменные), узел Python, куб, подключения к
базам данных, публикация сценария как веб-сервиса.

## Новый компонент

1. Функция и описание в `runner/studio/components.py` (`COMPONENTS`), тест — `runner/studio/test_studio.py`.
2. Каталог для платформы: `python studio/catalog.py > studio/catalog.json` (в папке `runner`;
   тест `test_catalog_file_is_current` следит, чтобы файл совпадал с кодом).
3. Редактор берёт форму настроек из каталога — править фронтенд не нужно, если хватает видов
   параметров (`text`, `number`, `bool`, `select`, `multiselect`, `column`, `columns`, `expr`,
   `rows`, `snapshot`).

## Развёртывание

Сервер: миграция 0026 применяется при старте бэкенда (`setup.sh`). Каталог компонентов бэкенд
читает из рабочей копии репозитория (`/repo`, уже смонтирована).

Компьютер лаборатории: новый исполнитель `runner-studio` (очередь `studio`) — после `git pull`:

    docker compose -f deploy\yandex\docker-compose.pc.yml --env-file deploy\.env up -d --build

Проверка: `docker logs esg-open-research-runner-studio-1` — строка `studio@… ready`.
