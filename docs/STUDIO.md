# Студия анализа

Сценарии обработки и анализа данных из узлов — перенос функционала Loginom (бывш. Deductor) на
платформу. Сайт: «Инструменты» → «Студия анализа».

## Как устроено

| Часть | Где | Что делает |
|---|---|---|
| Редактор | `frontend/src/pages/StudioEditor.tsx` (React Flow) | холст узлов, палитра, настройки узла, «Таблица» и «Статистика» результата |
| Сценарии | `backend/app/api/studio.py`, таблицы `scenarios`, `scenario_versions`, `studio_runs` (миграция 0026) | SC-NN, версии, права, постановка расчёта, приём итога |
| Движок | `runner/studio/` (`engine.py`, `components.py`, `expr.py`, `stats.py`) | проверка сценария, счёт узлов по связям, компоненты, выражения |
| Исполнитель | `runner/worker/tasks.py`: задача `runner.studio`, очередь `studio` | сверка sha256 входных файлов, расчёт, итог платформе |

Сценарий — JSON (`format: 1`): узлы (`id`, `type`, `params`, координаты) и связи
(`from` → `to`, вход `port`). Каждое сохранение — новая версия; расчёт записывает версию сценария,
sha256 каждого входного файла, коммит runner и хеш окружения (правило 3).

**Предпросмотр узла** («Посчитать узел») считает только узел и то, от чего он зависит; первые
100 строк результата и статистика по столбцам приходят на сайт, файлы не сохраняются.
**Расчёт сценария** считает всё; узлы «Экспорт: Файл» сохраняют CSV/Excel в папку данных
(`studio/SC-NN/run-NNNNN/files/`), их можно скачать со страницы сценария. Ошибка узла не
останавливает остальные: не считаются только узлы после него.

Права: смотреть — все вошедшие; создавать, менять, считать — researcher+; менять — автор или
владелец платформы (остальные — «Сделать копию»). Результаты по набору под NDA видны только тем,
кому видны его файлы (правило 6).

## Компоненты (этап 1)

Импорт: **Набор данных** (версия набора платформы — CSV или лист Excel).
Экспорт: **Файл** (CSV или Excel).
Трансформация (как в Loginom): Группировка, Разгруппировка, Дата и время, Дополнение данных,
Замена (точно / регулярным выражением), Калькулятор, Кросс-таблица, Объединение, Параметры полей,
Свёртка столбцов, Скользящее окно (лаги и прогнозный горизонт, в т.ч. внутри групп — панели),
Слияние (внутреннее, левое, правое, полное, разность), Соединение, Сортировка, Фильтр строк.
Визуализаторы: Таблица, Статистика.

**Выражения** (Калькулятор, Фильтр строк) — как в Excel: `выручка / сотрудники`,
`ЕСЛИ(roe > 0.1; "высокая"; "низкая")`, `ГОД(дата) >= 2020 И НЕ ПУСТО(отрасль)`; столбец с пробелами —
в обратных кавычках: `` `доля, %` ``. Функции: ЕСЛИ, ABS, КОРЕНЬ, LN, EXP, ОКРУГЛ, МАКС, МИН, ПУСТО,
ПЕРВОЕНЕПУСТОЕ, ГОД, КВАРТАЛ, МЕСЯЦ, ДЕНЬ, ТЕКСТ, ЧИСЛО, ДЛСТР, ПРОПИСН, СТРОЧН, СЖПРОБЕЛЫ, СЦЕП
(и английские имена). Разбирает свой разборщик с белым списком — произвольный Python не выполняется.

## Компоненты (этап 2)

Предобработка (`runner/studio/preprocess.py`): **Заполнение пропусков** (среднее, медиана, частое,
значение, предыдущее/следующее, интерполяция, удалить строку — в т.ч. внутри групп), **Квантование**
(равной наполненности, ширины, свои границы), **Конечные классы** (классы по связи с бинарным
целевым, WoE), **Разбиение на множества** (обучающее/тестовое/валидационное, группа целиком в одно
множество, стратификация, seed), **Редактирование выбросов** (IQR, z, квантили: обрезать, пусто,
удалить, отметить), **Сглаживание** (скользящее среднее/медиана, экспоненциальное, внутри групп),
**Сэмплинг** (долей, числом, по слоям, бутстреп, seed), **Нормализация** (z, 0…1, медиана/IQR,
логарифм; дискретные — столбцы 0/1, номер, частота).

Исследование (`runner/studio/research.py`): **Корреляционный анализ** (Пирсон, Спирмен, Кендалл —
парами с p-значением и силой, с целевым или матрицей), **Факторный анализ** (главные компоненты,
число факторов по Кайзеру, варимакс; нагрузки и доля дисперсии или факторы в строки),
**Автокорреляция** (ACF, частная PACF, граница значимости), **Дубликаты и противоречия**.

Визуализаторы: **Качество данных** (пропуски, выбросы, нули, числа текстом, постоянные столбцы,
повторы строк) и **Диаграмма** (гистограмма по всем строкам; столбцы, точки, линия — по случайной
выборке до 500 строк у узла, посчитанного «Посчитать узел»).

## Компоненты (этап 3) — Data Mining

`runner/studio/mining.py`: **Линейная регрессия** (МНК: коэффициенты, ст. ошибки, p-значения, R²,
скорректированный R², F; текстовые признаки — столбцами 0/1), **Логистическая регрессия**
(отношения шансов, p-значения, AUC, ROC, матрица ошибок), **Нейросеть (регрессия)** и
**Нейросеть (классификация)** (многослойный перцептрон), **Кластеризация** (k-средних, число —
по силуэту), **EM-кластеризация** (смесь нормальных, число — по BIC), **Самоорганизующиеся сети**
(карта Кохонена), **Ассоциативные правила** (Apriori: поддержка, достоверность, лифт),
**Кластеризация транзакций**, **ARIMAX** (p, d, q, внешние факторы, прогноз на горизонт; оценка
CSS).

Валидация моделей: столбец множеств из «Разбиения» — модель учится на обучающем, метрики — на
обучающем и тестовом; кросс-валидация по k частям. Вход «Новые данные» (необязательный) — модель
применяется к ним. Визуализатор **Отчёт**: метрики по множествам, коэффициенты, профили
кластеров, ROC-кривая.

## Компоненты (этап 4) — управление, переменные, Python, куб

Управление (`runner/studio/control.py`): **Условие** (ветка дальше, если выполнено: `$СТРОК > 10`;
иначе пустая таблица или остановка), **Узел-ссылка** (результат другого узла без линии),
**Выполнение узла** (таблица дальше — только после указанных узлов), **Подмодель** (другой сценарий
как узел: данные — в его «Вход подмодели», результат — из «Выхода подмодели»), **Цикл**
(подмодель для каждого значения столбца, внутри — `$ЦИКЛ`, итог — одной таблицей).
Платформа вкладывает граф подмодели в расчёт той версией, что была при запуске, и записывает её
в расчёт; вызов самой себя и вложенность глубже 5 — ошибка.

Переменные: у сценария — свои (панель «Переменные сценария»), в формулах — `$имя`. Компоненты
**Таблица в переменные**, **Переменные в таблицу**, **Калькулятор (переменные)**, **Замена
(переменные)**, **Соединение (переменные)**. Узел видит переменные сценария и всех узлов перед ним.

**Python** (`runner/studio/python_node.py`): свой код — `df`, `df2`, `vars`, `pd`, `np` → `out`.
Код проверяет `runner/studio/pycheck.py` (и платформа до запуска, и исполнитель перед
выполнением): только библиотеки расчётов, без файлов, сети, процессов, eval/exec и служебных
атрибутов. Считать код другим людям можно только после одобрения владельцем платформы
(«Одобрить код» на узле; одобрение — по sha256, изменили код — одобрять снова; миграция 0027).

Визуализатор **Куб**: у узла, посчитанного «Посчитать узел», — сводная по измерениям (столбцы с
2–50 значениями, без идентификаторов) и мерам: сумма, среднее, количество, минимум, максимум,
с итогами. Узлы сценария, собранного через API без координат, редактор раскладывает по слоям.

## Компоненты (этап 5) — базы данных и веб-сервисы

**Подключения к базам** («Служебное» → «Подключения к базам», только владелец платформы):
PostgreSQL, MySQL/MariaDB, MS SQL Server, ClickHouse. Код DB-NN, пароль хранится зашифрованным
(`app/services/secrets.py`: Fernet, ключ — из `SECRET_KEY` сервера; сменили `SECRET_KEY` — пароли
ввести заново) и никому не показывается. Исполнитель получает реквизиты от платформы по своему
токену только пока идёт расчёт и только подключений этого сценария (`GET
/api/studio/worker/{run}/connections`), процессу расчёта — в переменной окружения, не в файлах.
База должна быть доступна с компьютера лаборатории (там идёт расчёт).

Узлы (`runner/studio/database.py`): **Импорт: База данных** — запрос SELECT/WITH (один, без команд
изменения; сеанс «только чтение» в PostgreSQL, MySQL, ClickHouse; для импорта лучше пользователь
базы только для чтения), не больше `max_rows` строк. **Экспорт: База данных** — дописать строки
или заменить таблицу; только для подключений с разрешённой записью; при «Посчитать узел» не пишет.
В расчёт записываются код подключения и sha256 запроса.

**Веб-сервис.** «Опубликовать как веб-сервис» на странице сценария (нужен ровно один «Выход
подмодели»): опубликованная версия считается по вызову

    POST /api/v1/studio/services/SC-NN/run
    {"inputs": {"in": [{...строки...}], "in2": [...]}, "wait": 30}

строки — во «Входы подмодели» (порт in / in2), ответ — таблица «Выхода подмодели» (до 100 000
строк): `{"run_id", "status", "output": {"columns", "rows", "total"}}`. Не дождались (wait до
60 с) — `GET /api/v1/studio/services/runs/{run_id}`. Нужен токен API «чтение и запуск»; одновременно
— до 3 вызовов на человека; данные вызова — до 5 МБ. Права, NDA, одобрение кода Python — те же,
что у обычного расчёта.

Окружение расчётов (`runner/hsu2025/requirements.lock`) дополнено драйверами psycopg, PyMySQL,
pymssql, clickhouse-connect — образ исполнителя нужно пересобрать (см. «Развёртывание»).

## Новый компонент

1. Функция и описание в `runner/studio/components.py` (`COMPONENTS`), тест — `runner/studio/test_studio.py`.
2. Каталог для платформы: `python studio/catalog.py > studio/catalog.json` (в папке `runner`;
   тест `test_catalog_file_is_current` следит, чтобы файл совпадал с кодом).
3. Редактор берёт форму настроек из каталога — править фронтенд не нужно, если хватает видов
   параметров (`text`, `number`, `bool`, `select`, `multiselect`, `column`, `columns`, `expr`,
   `rows`, `snapshot`).

## Развёртывание

Сервер: миграции 0026–0028 применяются при старте бэкенда (`setup.sh`). Каталог компонентов
бэкенд читает из рабочей копии репозитория (`/repo`, уже смонтирована).

Компьютер лаборатории: исполнитель `runner-studio` (очередь `studio`); после `git pull` и после
изменений `requirements.lock` (этап 5 — драйверы баз) пересобрать оба исполнителя:

    docker compose -f deploy\yandex\docker-compose.pc.yml --env-file deploy\.env up -d --build

Проверка: `docker logs esg-open-research-runner-studio-1` — строка `studio@… ready`.
