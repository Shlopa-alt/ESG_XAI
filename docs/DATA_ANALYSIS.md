# Модуль анализа данных и нейросетей — проект

Задачи 8, 9, 11, 13 из «Задачи: модуль анализа данных и ИНС» (ноябрь 2026). Документ — для встречи
с лабораторией: сценарий, экраны и API. Правила домена — `CLAUDE.md`, ТЗ — `docs/SPEC.md`.

## Зачем

Лаборатория просила, чтобы платформа не только собирала идеи из статей, но и помогала проверять их
на данных: подбирала подходящую нейросеть под задачу, запускала расчёт и показывала его цену заранее.
Эксперт не должен знать библиотеку методов, чтобы получить расчёт: он выбирает, **что** изучает
(показатель или пункт методики) и **на чём** (набор данных), платформа предлагает, **как**.

## Сценарий (задача 8)

1. Меню → **Анализ данных**.
2. **Что изучаем.** Пункт методики (необязательно) и набор данных с версией. У книги Excel — лист.
3. **Показатель.** Целевой показатель R из числовых столбцов. Если выбран пункт методики, платформа
   ставит наверх столбцы, похожие на результат пункта (ROA, выручка, налоги…), и пишет почему.
   Без показателя — «сравнить показатели между собой» (согласованность).
4. **Рекомендация.** Платформа смотрит на данные (строк, числовых и текстовых столбцов) и тип задачи
   и предлагает метод с объяснением; рядом — альтернативы. Параметры уже заполнены: входы X — числовые
   столбцы, параметры Z — текстовые с немногими значениями (отрасль, регион). Их можно поправить.
5. **Цена расчёта** (задача 11): где посчитается (процессор / видеокарта), сколько минут примерно,
   лимит метода, сколько расчётов впереди в очереди, сколько осталось от дневной квоты.
6. **Запустить расчёт** — одна кнопка: платформа создаёт проверку `EXP-NNN` (пункт методики, данные,
   метод, причина выбора) и ставит расчёт в очередь. Дальше — обычная страница расчёта с живым ходом.
   Расчёт фиксирует коммит runner, хеш версии данных, окружение, seed и конфиг (правило 3).

Отрицательный итог («нейросеть не лучше среднего») — нормальный результат и публикуется так же (правило 4).

## Подбор сети по статье (задача 9)

Классификация «тип задачи → рекомендуемые сети» — `backend/app/services/net_catalog.py`:

| Тип задачи | Пример | Сети и методы (порядок — рекомендация) | Считается в платформе |
|---|---|---|---|
| Прогноз числового показателя | ROA по ESG-входам, R = f(X, Z) | перцептрон (MLP) → трансформер для таблиц → бустинг и линейная модель | да: `lab-mlp`, `predictive-check` |
| Согласованность показателей | рейтинги разных агентств | ранговая корреляция (сеть не нужна) | да: `rank-agreement` |
| Отнесение к классу | буква рейтинга, дефолт | перцептрон-классификатор, бустинг | пока нет |
| Прогноз по годам | ряд показателя компании | LSTM, трансформер | пока нет |
| Тексты отчётов | гринвошинг | языковая модель (BERT) | пока нет |
| Связи между компаниями | цепочки поставок | графовая сеть (GNN) | пока нет |

Если у идеи для проверки есть статья-источник, платформа ищет в её тексте, какой сетью пользовались
авторы (MLP, трансформер, LSTM, бустинг…), и предлагает сначала **«как у авторов»** — ту же сеть, а
затем альтернативы того же типа задачи (например, перцептрон → трансформер). Выбор, его причина и
цитата из статьи записываются в проверку (`config.analysis`) и видны на её странице.

Сеть, которой в платформе нет, показывается честно: «у авторов — LSTM, в библиотеке её пока нет;
ближайшая доступная — …».

## Учёт ресурсов (задача 11)

* **Оценка до запуска** — `POST /api/runs/estimate`: ресурс, минуты (с разбросом), лимит метода,
  очередь, квота. Оценка — по формуле метода (строки × входы × разбиения × испытания) и, когда
  накопилось хотя бы три завершённых расчёта того же метода, поправляется по их фактическому времени.
* **Оптимальный способ.** Если оценка больше лимита метода, платформа предлагает уменьшить число
  испытаний подбора (разбиения по протоколу CR-01 — не меньше 30) и показывает новую оценку.
  Видеокарта выбирается, только если её исполнитель включён (`GPU_EXECUTOR=true`) и сеть выигрывает
  от неё (трансформер); сейчас исполнителя видеокарты нет — считаем на процессоре.
* **Лимиты на сервере** (не только в интерфейсе), `deploy/.env`:
  `RUN_ACTIVE_PER_USER` — сколько расчётов человека может ждать и идти одновременно,
  `RUN_CPU_MINUTES_PER_DAY` — дневная квота оценённых минут (администратор не ограничен),
  `GPU_RUNS_PER_USER` — как раньше. Расчёт, который по оценке не уложится в лимит метода, не ставится.
  Оценка записывается в запуск (`config.estimate`), чтобы потом сравнить с фактом.

## Агент сбора данных из статей (задача 13)

Задача Qwen `data_links` (обработчик на машине лаборатории, `runner/qwen/worker.py`):

1. Проходит по статьям банка (или по одной), берёт текст из разметки docling.
2. Находит ссылки на данные: репозитории (Zenodo, figshare, Mendeley Data, Dataverse, Dryad, OSF,
   GitHub, Kaggle, сайты статистики), DOI наборов данных, прямые ссылки на CSV/XLSX, фразы вида
   «data are available at…». Qwen отбирает ссылки на данные **самих авторов** и описывает их.
3. Скачивает доступное: только http(s) и только публичные адреса (проверка на каждом
   перенаправлении), не больше `LINK_MAX_MB`; страницу Zenodo и figshare разворачивает в файлы.
4. Платформа разбирает файл (CSV/XLSX) и кладёт в «Данные → Данные из статей» черновик набора.
   В черновике — ссылка на статью, ссылка на источник данных, адрес скачанного файла и его sha256,
   журнал обработки и пометка «условия использования определяет статья» (правило 8).
   Ссылку, по которой файл скачать нельзя (вход, капча, страница без файла), агент тоже кладёт
   черновиком без таблицы — человек скачивает сам.
5. Дальше — как с таблицами статей: правка, «Создать набор данных» (DS-NN) или «Отклонить».

## API

| Метод | Адрес | Кто | Что |
|---|---|---|---|
| GET | `/api/analysis/catalog` | вошедший | типы задач и сети, какие считаются |
| POST | `/api/analysis/recommend` | вошедший | `{snapshot_id, sheet?, target?, node?, hypothesis?}` → столбцы, кандидаты в показатель, тип задачи, рекомендации с причинами, «как у авторов» |
| POST | `/api/analysis/launch` | researcher+ | `{snapshot_id, template, params, node?, hypothesis?, choice}` → проверка `EXP-NNN` и расчёт |
| POST | `/api/runs/estimate` | вошедший | `{template, snapshot_id, params}` → ресурс, минуты, лимит, очередь, квота, совет |
| POST | `/api/data-drafts/links-scan` | researcher+ (все статьи — администратор) | поставить агента сбора данных |
| POST | `/api/qwen/worker/links-context`, `/worker/link-drafts` | обработчик Qwen | какие ссылки уже разобраны; черновики с файлами |

NDA: рекомендация читает столбцы среза — для набора под NDA только с допуском, как и выгрузка файлов.

## Экраны

* **Анализ данных** (`/analysis`): три шага на одной странице — «Что изучаем», «Показатель»,
  «Рекомендация и запуск». Карточка рекомендации: метод, почему он, параметры (свернуть/раскрыть),
  цена расчёта, кнопка «Запустить расчёт». Альтернативы — такими же карточками ниже.
* **Идеи для проверки**: у принятой идеи со статьёй — «Подобрать сеть» → та же страница с идеей:
  первой стоит карточка «Как у авторов».
* **Страница проверки**: блок «Почему этот метод» — тип задачи, сеть, «как у авторов» или замена,
  цитата из статьи.
* **Данные из статей**: у черновика — откуда он (таблица статьи или ссылка на данные), ссылки на
  статью и источник, кнопка «Найти данные по ссылкам из статей».
