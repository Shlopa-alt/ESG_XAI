# Открытый API

Свои программы, скрипты и внешние системы подключаются к платформе через HTTP API: наборы данных и их
версии, расчёты, проверки, методика, идеи — то же, что на сайте. Описание всех методов с параметрами
и ответами — на самой платформе: **`https://<адрес>/api/docs`** (там же можно вставить токен кнопкой
«Authorize» и пробовать запросы); схема OpenAPI — `/api/openapi.json`.

## Доступ: личный токен

1. На сайте: вверху **API** → «Доступ к API» → «Новый токен»: название, права, срок (до 365 дней).
2. Токен (`esg_…`) показывается **один раз** — сохраните его в переменной окружения или менеджере
   паролей. В базе платформы хранится только его хеш.
3. Каждый запрос — с заголовком `Authorization: Bearer esg_…`.

| Права токена | Что можно |
|---|---|
| только чтение | любые `GET`: наборы, версии и файлы данных, расчёты, проверки, методика |
| чтение и запуск | ещё изменения: запуск расчётов, создание проверок, загрузка `run.json` |

Токен действует с правами **вашей роли** (reader / researcher / reviewer / owner) и не больше их:
файлы под NDA — только при допуске (правило 6), лимиты и квоты расчётов — те же, что на сайте.
Каждое изменение через API — в журнале аудита с пометкой «(API)».

Через API **нельзя** управлять учётной записью: выпускать токены, менять пароль и почту, управлять
пользователями — только со входом на сайте. Утёкший токен не даёт выпустить себе новый.

Токен перестаёт действовать, когда: истёк срок; его отозвали («Доступ к API» → «Отозвать»);
владелец платформы сбросил пароль или заблокировал пользователя. Владелец платформы видит и
отзывает токены всех («Показать токены всех пользователей»).

## Адреса

Постоянные адреса — с версией: `/api/v1/…`. Сейчас это то же, что `/api/…` без версии; при
несовместимых изменениях появится `/api/v2/`, а `v1` останется.

## Примеры

```bash
export ESG_TOKEN=esg_…
curl -H "Authorization: Bearer $ESG_TOKEN" https://<адрес>/api/v1/datasets
curl -H "Authorization: Bearer $ESG_TOKEN" https://<адрес>/api/v1/runs/57
```

```python
import os, requests
api = requests.Session()
api.headers["Authorization"] = "Bearer " + os.environ["ESG_TOKEN"]
BASE = "https://<адрес>/api/v1"

datasets = api.get(f"{BASE}/datasets").json()
estimate = api.post(f"{BASE}/runs/estimate", json={
    "template": "correlation-scan", "snapshot_id": 12, "params": {"method": "partial"}}).json()
```

Командная строка `esg` (`cli/README.md`): `esg login --token --url https://<адрес>` или
переменная `ESG_TOKEN` — дальше все команды (`esg datasets`, `esg launch …`) идут по токену.

## Ответы и ошибки

JSON; ошибка — код HTTP и `{"detail": "текст по-русски"}`:

| Код | Значит |
|---|---|
| 401 | токена нет, он отозван, истёк или пользователь заблокирован |
| 403 | не хватает прав роли или токена («только чтение»), либо это управление учётной записью |
| 404 | нет такого объекта (или он скрыт правами) |
| 409 / 422 | действие сейчас невозможно / неверные параметры — причина в `detail` |
