# ESG Open Research — платформа открытых исследований

Внутренний веб-сервис лаборатории НИЦ ИИ (Университет «Дубна»). Доступен только из внутренней сети.
Цель: дорабатывать методологию ESG-анализа через цикл
**база знаний → гипотеза → эксперимент → изменение методологии (CR)**.

Полное ТЗ: `docs/SPEC.md`. Экраны макета: `design/` (описание в `design/README.md`).
Перед любой задачей по фронтенду открой соответствующий `design/*.dc.html` и повтори структуру и токены.

## Стек

- Backend: Python 3.11, FastAPI, SQLAlchemy 2 + Alembic, PostgreSQL 16, Pydantic v2
- Очередь запусков: Celery + Redis; трекинг экспериментов: MLflow (self-hosted)
- Живой поток метрик и логов: Server-Sent Events (`/api/runs/{id}/stream`)
- Frontend: React 18 + TypeScript + Vite, React Router, TanStack Query; граф: Cytoscape.js; графики: Recharts
- Авторизация: LDAP университета (ldap3), сессия в httpOnly cookie
- Развёртывание: docker compose, nginx как обратный прокси с ограничением по подсети

## Структура репозитория

```
backend/      FastAPI-приложение (app/api, app/models, app/services, app/workers)
frontend/     React-приложение (src/pages, src/components, src/api)
runner/       скрипты экспериментов, которые запускает Celery (каждый пишет в MLflow)
design/       макеты экранов (.dc.html) и токены дизайна
docs/         ТЗ и архитектурные решения
deploy/       docker-compose.yml, nginx.conf, .env.example
```

## Команды

- `docker compose -f deploy/docker-compose.yml up -d` — поднять всё
- `cd backend && alembic upgrade head` — миграции
- `cd backend && pytest` — тесты бэкенда
- `cd frontend && npm run dev` / `npm run build` / `npm test`

## Правила домена (не нарушать)

1. У каждой сущности платформы человекочитаемый код: `DS-01` (датасеты), `EXP-001`, `CR-01`. Код неизменяем. Статьи и факты базы знаний живут в KBRAG и адресуются его идентификаторами (`doc_id`, id факта).
2. Изменение раздела методологии — только через CR. CR можно перевести в «Принято», если есть хотя бы одно основание (завершённый эксперимент, проверенный факт KBRAG с цитатой или статья KBRAG с DOI/ссылкой) и хотя бы одна одобряющая рецензия. Проверка на бэкенде, не только в UI.
3. Каждый запуск фиксирует: git-коммит runner, версию (хеш) среза данных, окружение, seed, конфиг. Без этого запуск не попадает в реестр.
4. Отрицательные результаты публикуются наравне с положительными. Статус «отклонена гипотеза» — нормальный исход.
5. Статья KBRAG без DOI и ссылки на источник помечается «требует источника» и не может быть основанием CR.
6. Данные под NDA (например, резиденты ОЭЗ): описание датасета видно всем, файлы и выгрузки — только роли с допуском; статьи под NDA — в отдельной ветке KBRAG с доступом по токену.
7. Никаких выдуманных данных в сидах и фикстурах: только реальные записи из `docs/SPEC.md` или явные заглушки `[...]`.
8. База знаний — внешний сервис KBRAG (`6snowyfox6/ESG`): платформа не копирует статьи и граф, а берёт их через `/api/kb/*`. Граф фактов редактируется только в KBRAG (правила графа и синонимы — `config/kbs/esg`).

## Роли

reader (чтение) · researcher (карточки, эксперименты, запуски) · reviewer (рецензии) · owner (принятие CR, версии методологии, доступы).

## Стиль кода

- Backend: ruff + mypy, тесты pytest на каждое правило домена из списка выше.
- Frontend: строгий TypeScript, ESLint, доступность (настоящие `<button>`, `<label>`, контраст ≥ 4.5:1).
- Интерфейс полностью на русском.
- Маленькие коммиты, одна задача — одна ветка — один PR.
