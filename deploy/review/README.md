# Стенд для рецензентов интерфейса

Одноразовая копия платформы из текущей рабочей папки: http://127.0.0.1:5180. База живёт в памяти и
создаётся заново при каждом запуске, данные — только реальные записи из миграций. С рабочим сервером,
`deploy/.env` и контейнерами вычислений на этой машине стенд не связан.

## Команды (из корня репозитория)

```bash
docker compose -f deploy/review/docker-compose.yml up -d --build proxy        # поднять или пересобрать после правок
docker compose -f deploy/review/docker-compose.yml run --rm --build capture --role researcher   # снимки и замеры
docker compose -f deploy/review/docker-compose.yml down -v                    # убрать
```

Параметры `capture`:

- `--role` — `reader`, `researcher`, `reviewer`, `owner` или `anon` (страница входа без учётной записи).
- `--routes experiments,run` — адреса без начальной косой черты; по умолчанию все страницы роли, `none` — только сценарий.
- `--widths 1440,768,390` — ширины экрана; по умолчанию `1440,390`.
- `--scenario scenarios/имя.mjs` — сценарий из `.review/scenarios/`, см. ниже. Он идёт на каждой ширине.

Результат — в `.review/<роль>/` (папка не попадает в git): снимки `*.png` всей страницы, `report.json` по
страницам и `report-<сценарий>.json` по сценарию. Смотри `taken_at`: снимки прошлых запусков остаются в папке.

Замеры на каждую страницу и ширину:

- `axe` — нарушения WCAG 2 A/AA, включая контраст;
- `horizontal_overflow_px` — вылет всей страницы;
- `inner_scroll` — блоки с прокруткой внутри и сколько пикселей в них скрыто: так прячутся столбцы таблицы, хотя вылета страницы нет;
- `targets_under_44px` и `text_under_12px` — мелкие цели нажатия и мелкий текст;
- `console`, `http` — ошибки консоли и ответы с кодом 400 и выше.

Войти руками: логин `review-<роль>`, пароль `review-stand`. Пароль известен всем и годится только
потому, что стенд открыт на 127.0.0.1 и не содержит закрытых данных.

## Сценарий пользователя

```js
// .review/scenarios/create-hypothesis.mjs
export default async ({ page, base, width, shot, step, tabWalk, invalidFields }) => {
  await page.goto(`${base}/hypotheses`);
  await shot("start");
  step("Открыл форму новой гипотезы");
  await page.getByRole("button", { name: "Предложить гипотезу" }).click();
  await shot("form");
  step(`Обход Tab: ${JSON.stringify(await tabWalk(5))}`);
  await page.getByRole("button", { name: "Отправить на рассмотрение" }).click();
  step(`Ошибки формы: ${JSON.stringify(await invalidFields())}`);
  await shot("empty-submit", { fullPage: false }); // подсказка браузера сдвигает снимок всей страницы
};
```

Встроенные подсказки браузера («Заполните это поле») Chromium на стенде показывает по-английски, у
пользователя они на языке его браузера. Английский текст такой подсказки — не дефект, а вот её вид,
отсутствие отметки обязательного поля и своей подсказки рядом с полем — предмет оценки.

Селекторы — по роли и подписи (`getByRole`, `getByLabel`): если элемент так не находится, это уже
замечание к доступности. Исключение в сценарии попадает в отчёт как `scenario.error` с последним снимком.
Замеры axe и вылета для места, где сценарий остановился, лежат в `scenario.final_state`: так проверяются
формы и диалоги, у которых нет своего адреса.

## Что стенд не показывает

- **База знаний и граф без данных:** KBRAG не подключён намеренно, иначе статьи, включая ветки под NDA,
  попадали бы на снимки и уходили во внешний API. Видно только состояние «база недоступна».
- **Запуски не выполняются:** исполнителя нет, запуск остаётся в очереди.
- **Qwen не работает:** нет обработчика и модели.
- **Мало данных:** видны только записи из миграций, поэтому таблицы могут быть короче, чем на сервере.

Проверить такой экран на стенде нельзя. В отчёте рецензент пишет «не проверено», а не выводит оценку.

Созданные при проверке записи остаются до `down -v`: это нормально, база стенда одноразовая.
